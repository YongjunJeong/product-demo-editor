# M6: CapCut 로컬 파일 교환

승인된 렌더 결과를 CapCut에서 마무리할 수 있는 폴더로 내보냅니다.
CapCut 내부 프로젝트 파일은 생성하거나 수정하지 않습니다. 앱이 없어도 내보내기와
무결성 검증을 사용할 수 있으며, 렌더나 ASR을 다시 실행하지 않습니다.

```bash
video-agent capcut-info
video-agent export-capcut work/m5-demo/approved.json work/m5-demo/final \
  --output work/capcut-demo --include-preview
video-agent verify-bundle work/capcut-demo
```

출력은 새 폴더여야 합니다. `--include-source`는 원본을 추가로 복사하며, 기본값은
원본과 미리보기 모두 제외입니다. 예제 결과는 `work/m6-capcut`에 있습니다.

| 파일 | 용도 |
|---|---|
| `edited.mp4` | 승인된 컷·배속을 반영한 영상, 자막은 구워 넣지 않음 |
| `subtitles.en.srt` | 편집 후 시간 기준의 별도 자막 |
| `approved-plan.json` | 승인된 계획과 원본 경로·해시 |
| `execution.json` | 원본/출력 프레임 대응 및 자막 시간 |
| `markers.json` | 컷·배속 구간 참고용 JSON; CapCut 마커 가져오기 형식 아님 |
| `IMPORT.md` | 가져오기 순서와 편집 가능 범위 |
| `bundle.json` | 각 파일 해시, 승인 해시, 길이, 감지된 앱 버전 |

내보내기는 승인 해시, 렌더 완료 상태, 계획·타임라인 일치, 영상 해시와 SRT 시간을
먼저 확인합니다. 복사 후 다시 검증하고 완료 manifest를 마지막에 기록합니다.
복사 실패로 남은 폴더는 완료된 번들로 취급하지 않으며 새 경로로 재시도합니다.
검증은 파일 손상·변경 감지이며 사용자 인증이나 서명은 아닙니다.

## CapCut 8.7.0 macOS에서 확인한 순서

1. 새 로컬 프로젝트를 만듭니다.
2. `edited.mp4`를 미디어로 가져와 타임라인 00:00에 배치합니다.
3. 재생 헤드를 00:00에 놓고 **캡션 → 캡션 추가 → 파일 가져오기**에서
   `subtitles.en.srt`를 선택합니다. 자막이 없는 빈 SRT는 건너뜁니다.
4. 가져온 SRT 항목의 **오른쪽 아래 추가 버튼**을 클릭합니다.
   파일을 가져오는 것만으로는 타임라인에 배치되지 않았습니다.
5. 자막 트랙을 선택해 문구, 위치, 글꼴과 색상을 확인합니다. SRT에는 스타일이 없으므로
   밝은 배경에서는 글자색이나 외곽선을 조정합니다. 프로젝트를 로컬에 저장합니다.

CapCut이 미디어 경로를 참조하므로 가져온 폴더를 임의로 이동하지 마세요.
`preview.mp4`는 자막이 이미 구워져 있어 별도 자막 편집용으로 사용하지 않습니다.

## 편집 가능 범위

자막은 독립된 텍스트 트랙으로 편집할 수 있습니다. 컷과 배속은 `edited.mp4`에 이미
반영되어 있습니다. 원본 클립별 컷·배속을 CapCut에서 복원해 주지는 않습니다.
원본 포함 옵션도 원본 복사만 수행하며, CapCut 타임라인을 재구성하지 않습니다.

2026-09-30에 설치된 CapCut 8.7.0에서 합성 영상 6.4초와 자막 한 개를 실제로
가져왔습니다. 별도 자막 트랙, `Normal speed.` 편집 필드, 재생 위치 00:00:03:25의
자막 표시, 검정색으로 스타일 변경 및 자동 저장 표시를 확인했습니다.
테스트는 새 프로젝트의 `타임라인 02`에서 수행했습니다. 다른 버전, 긴 영상,
실제 제품 데모, CapCut 최종 내보내기 결과는 이번 검증에 포함되지 않습니다.

`capcut-info`와 `verify-bundle`의 `ui_import_verified: false`는 해당 명령이 UI 검증을
수행하지 않는다는 뜻입니다. 설치 감지나 파일 해시 검증만으로 호환 성공을
자동 선언하지 않습니다. 위 실기 검증 기록과 구분합니다.
